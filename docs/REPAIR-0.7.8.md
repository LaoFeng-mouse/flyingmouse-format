# 0.7.8 启动兼容性修复候选

作者：牢蜂（LaoFeng）。仅供个人免费使用，禁止商业售卖、转卖及套壳。

2026-09-18，从保留的 0.7.6 隔离复制。当前渠道：公开功能版。仅本地构建和验收，尚不代表安装验收、客户现场修复或公开发布。0.7.7 CAD 工作保持暂停，本候选不包含 PDF → DWG。

## 已确认的诊断

在同一份 0.7.5 启动载荷及同一 profile 上，给 icudtl.dat 单文件添加指定 App Package SID 的 Allow ACE 可触发六次 GPU 子进程崩溃和最终 FATAL；保留该 ACE、仅补读取授权可恢复启动。Windows API 派生的标准形状 SID 也完成同样对照，故不能仅归因于短合成 SID 的形状。首个 GPU 异常位于 ICU 初始化，离线反汇编和保留的错误值支持文件读取被拒绝。普通未知用户 SID、仅 Runtime.exe 权限变化和不继承的目录权限变化未复现该故障。

这些是本机受控复现，未取得客户现场同一文件的 ACL 和首个异常栈。不能宣称客户安装目录已确认存在该问题，也不能宣称 Windows 内核解释该 ACE 的具体分支已经证实。六次子进程重试不是六轮独立实验。

## 本轮修复范围

- 原生入口在启动 Electron 前检查所需资源访问；恢复措施仅限本应用范围，并保持 GPU 与渲染器沙箱。不修改系统 NUL，不全局重置 ACL，不批量删除未知 SID。
- 改善启动日志位置不可写时的降级与原始错误报告。
- 将用户配置和日志的早期初始化错误纳入明确提示及退出路径，保留既有 profile 和用户数据。
- 核对非 Store Windows 打包版本的 Agent CLI 与任务栏重启入口，避免绕过原生启动器。

以上描述为候选实现及验收目标；每项完成状态以本轮测试和最终安装验收记录为准。

## 2026-09-18 本机验证进展

扩大到整个安装目录继承权限后，又复现渲染器延迟加载 ffmpeg.dll 失败。首个异常栈位于 MSVC _delayLoadHelper2，错误 126 / 0xC0000135，与此前 ICU 读取失败为两个阶段。仅给 DLL 补读取权限不足；给根目录 DLL 补读取和执行权限的对照通过，app.asar 无需新增授权。

最终原生入口编译绑定 68 项资源及 SHA-256：60 项数据仅允许读取，8 个根目录 DLL 允许读取和执行。只有普通读取成功、低完整性受限令牌在打开文件时返回拒绝访问，且文件位于安装目录、内容哈希符合本次构建，才尝试补充所需授权。显式拒绝策略、重解析文件、硬链接、内容变化和没有修改权限的情况不强行修复；不授权写入，不关闭沙箱，不提升权限。正常读取时不进行全量哈希校验，故不能把启动检查当成完整防篡改验证。

本机 Windows 11 26200，非提升用户令牌：

- 本地音乐版和公开渠道最终 0.7.8 均通过整个安装目录继承异常权限后的真实 GUI 启动；68 项自动处理，GPU low、渲染器 untrusted，均保持 sandboxed=true。测试后全部 ACL 和文件字节恢复。
- 中文、空格路径下的本地版真实 GUI 启动通过。此路径用指向同一构建的目录联接验证，不代表另一次安装器安装。
- 7 项最终原生回归全部通过：普通检查、拒绝访问、自动修复、幂等、显式拒绝、内容变更和没有 WRITE_DAC 权限。
- 日志主目录不可用时转临时目录；两处不可用时仍有有效且持续排空的输出管道。独立测试同时覆盖探测令牌无法设置时不改权限。测试钩子未加入产品。
- 最终源码完整测试均零失败：本地版预检 116，通过 851、跳过 11；公开版预检 116，通过 767、跳过 9。跳过项包括缺失可选样本、平台专属或当前引擎配置不适用场景。
- 实包检查发现 Electron 在 main 首行前会把不可用的显式 user-data-dir 回退到默认 profile。最终版直接读取并校验原始参数，拒绝空值和普通文件，恢复有效显式目录的优先级；真实 CLI 错误时 exit 1，默认配置和日志在修复后的专门对照中未被业务写入。有效中文配置路径通过。
- 最终真实原生入口完成 PNG→JPEG、WAV→MP3 完整解码、中文 DOCX→一页 PDF→TXT 与受污染开发环境变量的回归。两版 ASAR 的应用入口均与冻结源码匹配，公开版不含本地音乐模块。
