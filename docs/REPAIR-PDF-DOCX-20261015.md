# PDF 转 Word 与合并修复

日期：2026-10-15。作者：牢蜂（LaoFeng）。仅供个人免费使用，禁止商业售卖、转卖和套壳。

本次将本地 R10 中的通用 PDF 修复移入公开源码分支。沿用现有普通音频边界，不加入平台专用音乐模块、账号接入、用户文档、机器诊断或安装器。来源版本的构建和安装验收不等于公开变体的构建或发布验收。

## 问题与改动

- 对具有原生文字、图片词条和页边标注的 PDF，逐字重建可能造成图片基线上移、下划线丢失、额外单字行或页边标注进入正文。现在在具备来源坐标及像素证据时保留相关整行图像，其余原生正文继续以文字写出；包含斜体笔画的裁区按实际范围扩展。
- 恢复实际空格与英文词边界，避免把解析器推断出的中文间距变成词内空格。移除导致部分 Word 渲染器相邻中文样式段重叠的横向缩放，采用 Word 原生字号精度。
- 生成的行内图片提供非空、唯一的 `wp:docPr/@name`。缺少该属性的文件可能通过 LibreOffice 渲染，却无法在 Microsoft Word 中正常打开。
- 输出校验比较正文、标点、大小写、空格、图片摘要、顺序和次数；允许整行图像的例外必须携带明确标记和真实图片引用，不能为普通无文字输出放宽检查。
- PDF 输入在进入转换或合并前验证文件头。仅文件名以 `.pdf` 结尾的文本会明确报错，不再进入后续 PDF 引擎或合并流程。合并继续检查输入与输出页数，拒绝缺页或伪成功。

## 验证与限制

回归包含构造 PDF、图文位置、斜体裁切、空格和标点、图片引用完整性、无效输入 HTTP 路由，以及真实 LibreOffice 中文间距。真实 Office 回归可通过 `FLYINGMOUSE_REQUIRE_REAL_OFFICE_CJK=1` 要求引擎存在并实际执行；不能将该项跳过当作兼容性通过。

本地来源 R10 已对四份有效 PDF（共 37 页）完成 GUI 转换与合并、Microsoft Word 普通打开和输出检查。用户原件与生成文档不随 Git 上传，这些结果也不能替代公开源码分支自身的验证；本分支测试结果见 [现役交接](HANDOFF.md)。

相关整行图像不能逐字编辑。字体、字重、行距、下划线及页码纵向位置仍可能与原件不同；不保证全文可编辑、任意 PDF 等价还原或修改文字后的分页。未在本公开分支重建安装器、验收 GUI、发布 Release 或更新 Microsoft Store。

既有公开分支的 LibRaw 锁定恢复及源码归档换行修复保留。未升级生产依赖，当前依赖风险须以独立审计记录为准，不能沿用旧版本的零漏洞结论。
