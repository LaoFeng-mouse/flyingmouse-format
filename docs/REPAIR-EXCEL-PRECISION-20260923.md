# PDF → Excel 精度复核与修复

2026-09-23 的源码修复记录，2026-10-03 整理为可移植的公开技术说明。来源版本为 0.8.1；原始文件与机器收据保留在本地，不包含在本分支。当前公开变体的验收见 [现役交接](HANDOFF.md)。

## 问题及原因

复现 PDF 是横向 A4 的表单。修复前已保留 13 列 × 21 行的文字，但文字齐全不足以证明版式准确。真实 Excel 复核发现：原来的仿宋被替换成微软雅黑、部分居中数据左对齐、表头填色与原件不符；表格左边比原件偏左约 16.3 mm，宽度少约 3.9%。收入表头在屏幕上会截断，打印与屏幕的换行结果也有差异。

根因涉及多层转换：字体/字号和对齐没有完整进入模型；原 PDF 用描边文字实现的加粗不能仅靠字体名称识别；PDF 点单位与 XLSX 字符宽度的换算没有固定 Normal 字体度量；Excel 的单元格留白及当前字体、显示缩放影响实际换行。ExcelJS 还会省略宽度恰好为 9 的列，需要明确 worksheet 默认列宽，防止 54 pt 列回落到应用默认宽度。

## 实现

- 模型携带原始字体、字号、倾斜、文字运行及对齐；保守映射 PDF 描边模式到原有强调，不从字体名猜测所有加粗。
- 有可靠几何信息的单页原生表单使用源纸张、物理坐标、行列宽、已识别文字字体和白底。未知字体可能采用替代，不能保证字形一致；纸张未知或几何歧义时才回到保守布局路径。
- 固定工作簿 Normal 字体为仿宋 12 pt，用于列宽度量；各单元格仍单独使用原件字体字号。两项新增运行模块已加入构建白名单。
- 为容纳 Excel 的表头留白，允许相邻列作有界宽度交换，单列累计让宽不超过 8 pt，总表宽不变，合并表头不参与。本实样收入列从邻列获得 7 pt，约 2.47 mm；保留原字体字号，不通过缩小文字掩盖截断。
- 普通数据行保持自动高度，长编号使用文本格式；收入允许数值。标题、签名、说明、页脚与主表在同一工作表。
- 小的可测排版空格保留文字并修正空白度量；大的词间空白保留原字体，不承诺精确还原。

## 剩余差异及交付边界

这次确认可编辑、文字一致、屏幕和打印完整，不声称逐像素复刻。原 PDF 的两个字体子集没有字体名称表，数字字形不能证明完全匹配；Excel 边框比原 PDF 略粗，签名和页脚仍有毫米级偏差。收入列约 2.5 mm 的局部加宽是为保持原字号并避免截断而做的明确折中。

本次实测环境为当前 Windows Microsoft Excel、150% 显示缩放；其他 Office 软件、字体环境、复杂/跨页/扫描 PDF 不能由这份样本的通过推断。填写长内容后允许行高增长，页数也可能随填写内容增长。

历史修正表格由转换代码直接生成，没有手工修补样式。公开分支仍须独立测试并整体重建入口、Runtime 和 ASAR，源码导入不表示旧安装包已更新。
