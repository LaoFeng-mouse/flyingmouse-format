# PDF 分式与扫描列关系修复（2026-09-28）

作者：牢蜂（LaoFeng）。仅供个人免费使用，禁止商业售卖、转卖和套壳。

本记录承接 [全面审查](AUDIT-PDF-20260928.md) 的两个 P1 缺陷。此前报告保留为修复前事实；公开变体当前状态以 [交接](HANDOFF.md) 为准。

## 修复范围

- `pdf-native-math.js` 从实际 PDF 横线、字形位置、字号、裁剪与绘制状态确认分数线及上下关系，将可确认的平面分式恢复为可编辑 Office Math。仅在唯一文字匹配与前后文锚点成立时改写；已有正确公式不会重复插入。相邻原生文字和等号共同证明的短矢量减号恢复为可编辑减号。字体已有的减号、普通标题线和表格边框不据此改造。
- 原生引擎、结构识别与无引擎文字降级的 DOCX 均在发布前应用数学修复并重新校验；嵌套分式、无法唯一对应的内容等已发现不支持情形返回 `PDF_NATIVE_MATH_UNVERIFIED`，不静默给出扁平公式。实际数学内容参与可编辑文字覆盖，但隐藏、脱离公式结构或伪造命名空间的文字不能充数。
- `pdf-scan-columns.js` 复核模型遗漏的无边框表格和已有表格内疑似粘连的数值。根据原图像素空白、独立 OCR 字符位置和列对齐重建单元格，完整对比原识别行。不会通过计算金额、截取数值字符串或推测小数点来生成数字。保留空白格、前导零和文本形式的金额；无法证明列关系或完整来源时返回 `PDF_SCAN_COLUMNS_UNVERIFIED`。
- DOCX/XLSX 返回列恢复警告；公式恢复提示可编辑但可能重排。HTTP 将上述两种明确拒绝作为稳定用户错误，CLI 保留警告。
- 修复扫描转 XLSX 输出校验卡住：大于 64 KiB 的参考图会触发 ZIP 库底层流停滞。改为从已验证的本地 ZIP 条目位置读取原始压缩流，保留本地/中央目录一致性、文件边界、压缩与解压实际大小、比例及资源上限，不整包读入内存。

## 保真边界

本次修复的是已证实的分式关系、矢量减号和扫描列关系，不保证任意技术文档逐像素或完整语义一致。并排分式可能重排为独立段落；常规原生引擎仍可能改变普通行内减法与正文的相对排版、遗漏装饰横线。扫描 OCR 的其他文字错误仍需人工对照原图；候选识别不等于通用表格或全部数学内容检测。

嵌套公式和无法确认来源的复杂扫描表格属于明确拒绝范围，不计作成功转换。原文件、修复前失败现场和旧包均保留。
