## 当时未解决的两项问题

### P1：原生数学分式损坏，仍显示无警告成功

使用正常 OMML 分式文档，经 LibreOffice 导出 PDF，再通过产品入口转 Word。原式 `x = (a+b)/(c-d)` 的分数线、分子/分母上下关系消失，输出成为 `x = a + b c - d`，并被移到后续正文末尾。原生引擎输出已损坏；文字覆盖检查只检查字符是否存在，返回 `missing=[]`，产品返回 `warnings=[]`。

这会改变数学含义。必须增加公式及几何结构的保真判断，不能仅补一个普通警告或按字符猜测重建公式。本轮保留复现，没有把它记作修复成功。

- 代码边界：[pdf.js](../pdf.js) 的 `missingPdfText`、`validateNativePdfDocx` 及原生输出验收。

### P1：扫描采购单的数量、单价、金额粘连

真实扫描 PDF 原件有清楚的四列间距。例如“鼠标 / 12 / 39.50 / 474.00”，输出成为一个 Word 文本节点 `鼠标1239.50474.00`；另一行为 `键盘889.00712.00`。实际 DOCX 没有对应表格、制表符或空格分隔，问题不是预览缩放。

捕获真实结构引擎清单后，确认引擎交给 Word 写出器的 `block.text` 已经粘连，`tables=[]`、`tableLike=false`、没有表格候选，警告为空。写出器原样使用该文本，没有额外删除空格。列信息在结构识别结果中丢失，又未触发表格检查。带电子页眉的混合扫描件同样受影响；它虽然有 `PDF_NATIVE_TEXT_RESTORED` 提示，但没有提示列关系损坏。

所有金额关键字符串仍能检索到，所以只断言“包含 474.00、712.00、1186.00”会误判通过。本轮将这两份 Word 的视觉/语义验收记为失败，未用测试成功掩盖。


## 四项已修复问题

| 级别 | 问题及影响 | 修复和验证 |
| --- | --- | --- |
| P1 | 整页 OCR 误识别原生编号/金额后，准确原文与错误副本同时输出，例如 `lO00123456789` 与 `1000123456789` | 按可靠坐标保留原生文字，只补独立扫描区域。相邻逐字 glyph 可联合覆盖，真正跨区域及无法证明的结果明确失败；不使用模糊字符串去重。真实 Courier/Times PDF、DOCX 及混合采购单验证通过。 |
| P2 | 普通标题横线、表格边框使已保留的原生插图被拒绝，又进入不必要的 OCR | 对已证明的直线路径、描边、CTM 及状态保存/恢复检查实际范围，仅允许与图片不相交的绘制。45 项关联测试通过；三份实际引擎输出正文及 RGB 图像摘要一致，均未进入 OCR。 |
| P2 | 用户取消 PDF 请求后后台仍能完成并登记下载结果 | PDF 路径接入断连信号，原生取消直接结束，不再进入其他转换回落；所有异步检查结束后再次检查连接，才登记下载。取消边界和正常请求分别验证。Tesseract 当前一次识别仍可能完成后才检查取消。 |
| P2 | CLI 非 JSON 输出只有路径，丢掉“图内文字仍为图片”等质量提示 | 质量警告写入 stderr；stdout 保留路径列表，JSON 保留原警告对象。CLI 及 HTTP 警告传递回归通过。 |

实现入口：[pdf.js](../pdf.js)、[server.js](../server.js) 与 [cli.js](../cli.js)。

来源版本的真实 HTTP 修后复测：正常原件转换、警告和下载通过；损坏 PDF 返回错误且未增加下载；在原生转换进行时断连，客户端收到 AbortError，后台未新增下载，上传临时文件已收尾，只保留之前正常任务的输出。此收据证明请求/输出生命周期，不是对所有引擎毫秒级终止的承诺。真实 CLI 默认模式现能在 stderr 看到页码、警告码和“图内文字仍为图片”说明。

此前已修的用户原始故障仍成立：七页工程 PDF 的第 6 页是原生正文加带图注的桥梁示意图，原生引擎已经保留文字和图片，却因“存在图片即需要 OCR”被再次送入识别，最终触发 `OCR_LOW_CONFIDENCE`。重复点击会再次触发同一路由。当前源码对这份原件的直接、HTTP、CLI 转换均成功，保留原文与精确图片像素，并提示图内文字仍不可编辑。详见 [原始修复技术记录](REPAIR-PDF-ILLUSTRATIONS-20260928.md)。
