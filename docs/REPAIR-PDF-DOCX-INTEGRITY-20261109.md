# PDF→Word 内容完整性修复候选（Issue #85）

作者：牢蜂（LaoFeng）。日期：2026-11-09。基线：`f7d9eab18e91848f9740261d348717bae3f40c21`。

状态：独立分支 `codex/issue85-docx-content-integrity-20261109`；通用源码修复候选，未合并主分支、发布版本或公开回复 [Issue #85](https://github.com/LaoFeng-mouse/flyingmouse-format/issues/85)。公开源码版本保持 0.8.4；独立本地集成验证见下文。

## 确认的缺口与修复

| 缺口 | 本次处理 |
| --- | --- |
| 原生文字层仅有页脚，矢量正文不进入文字或栅格图片覆盖检查 | 提取时标记待核对路径；Word 转换前比较原页与去除可疑路径的渲染。存在可见差异就明确拒绝，避免原生输出和回退输出都只剩页脚却报成功。 |
| 文字比较去掉标点，`1186.00` 与 `118600` 等价 | 覆盖比较保留标点；仍允许空白、兼容字形、Word 文本节点拆分和表格重排。OCR 合并原有规范化算法不变。 |
| 一次输出文字可满足多个相同源片段/页面 | 核对每个片段的非重叠出现次数，并累计源字符需求，避免跨片段重用同一批字符。 |
| 隐藏 `w:t` 和零宽字符能证明“有正文” | 按命名空间及实际 XML 顺序读取正文，解析 styles 关系、文档默认值、段落/字符样式继承与直接 vanish 覆盖；排除删除、非正文及不可确认的兼容分支。未知或循环样式不能建立可见性证明。 |
| 最终纯文字重建只有基本 DOCX 验证 | 发布前同时核对原生源片段和 OCR 补全后的行。失败保留已有目标文件，清理本次临时输出。 |

矢量检查使用实际渲染处理透明、裁剪和后续遮挡，并参与图像内存预算和取消流程。表格细线、横线和包含原生字形的矩形底色仅作有限豁免；Form XObject 的矩阵参与坐标判断，复杂图形组不直接豁免。渲染器缺失或无法证明时明确失败。HTTP 对内容未确认、正文为空和覆盖失败返回 422，进度标为失败，不注册下载，也不写 `Convert succeeded`。

样式中的 vanish 按切换属性处理，直接格式按绝对开关处理；参见 [Microsoft Open XML 文档](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.vanish?view=openxml-3.0.1)。

## 仍需真实文件确认的边界

这些合成文件和源码能确认上述缺口，不能证明它们就是 Issue #85 的实际根因。该截图只见 TCPDF 页脚，原 PDF、生成 DOCX 和版本仍未取得。

当前方案是保守阻止不可信成功，不恢复一般矢量文字；复杂装饰图可能被明确拒绝。DOCX 验证也不是完整 Word 渲染器：白色文字、文本框位置、复杂样式/字体和各办公软件显示差异仍不能由本次检查普遍证明。Windows 7 旧 PDF.js 无 operationsFilter 时拒绝可疑矢量页面；本轮未验证 Win7、macOS、公开变体安装包或原 Issue 文件。

要确定 Issue 的实际原因，最少需要同一次转换的原 PDF 与生成 DOCX、飞鼠格式版本/安装渠道，以及打开 DOCX 的 Word/WPS 名称和版本。可提供保持问题的最小脱敏样本；已有日志和截图可直接用于对照，无需重复公开发送。
