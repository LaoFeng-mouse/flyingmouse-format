# 转换稳定性与操作记忆设计

## 目标

本次改动解决三个已确认问题：

1. LibreOffice 冷启动超过 5 秒时被误判为不可用，导致文本和文档目标格式消失。
2. DOCX 转 Markdown/TXT 的纯 JavaScript 路径被错误地绑定到 LibreOffice 可用状态。
3. 用户每次重新上传同类文件都要重复选择目标格式和保存目录。

NCM 支持范围保持不变：只保证 `music163.com` 官方客户端下载的标准 NCM 文件，不扩展其他网站来源的变体。

## LibreOffice 与文档目标

- 初始能力探测允许 LibreOffice 最多冷启动 30 秒。
- 实际转换不再先重复执行 `soffice --version`；直接运行 `--convert-to`，由真实转换结果决定成功或失败。
- DOCX 无论 LibreOffice 是否可用，都提供 Markdown 和 TXT 目标，因为这两条路径使用 Mammoth/Turndown，不依赖 LibreOffice。
- DOC、ODT、RTF、WPS 等其他文档仍只在 LibreOffice 可用时提供对应目标。
- API 能力列表与单文件 `/api/targets` 的实际行为保持一致，不宣传当前不可用的转换。

## 目标格式记忆

- 渲染层使用版本化的 `localStorage` 键保存 `{ 源扩展名: 最近目标格式 }`。
- 扩展名按现有规范统一，例如 `jpeg -> jpg`、`markdown -> md`、`htm -> html`、`tif -> tiff`。
- 用户手动改变目标下拉框时，将当前目标写入本次所选文件涉及的每一种源扩展名。
- 单文件或同扩展名批量上传时，如果记忆目标仍在当前可用目标中，自动选中该目标。
- 混合扩展名批量上传时，仅当所有扩展名的记忆目标一致且属于共同目标交集时自动选中；否则使用当前默认选项，让用户手动决定。
- localStorage 缺失、损坏或浏览器禁用时静默退化，不影响转换。
- 不自动开始转换，仍由用户点击“开始转换”，避免上传即执行造成误操作。

## 保存目录记忆

- 保存目录由 Electron 主进程持久化到 `app.getPath("userData")` 下的 JSON 设置文件，不将本地绝对路径暴露给网页存储。
- 单文件保存对话框的 `defaultPath` 使用“最近保存目录 + 输出文件名”。
- 批量保存目录选择器的 `defaultPath` 使用最近保存目录。
- 只有用户实际完成保存后才更新最近目录；取消对话框不覆盖原有记忆。
- 设置文件不存在、JSON 损坏、目录已被删除或不是目录时，回退到系统 Downloads。
- 写设置采用临时文件后替换，减少异常退出造成半写文件的风险。

## 安全与兼容性

- 保持现有 renderer/main IPC 信任边界；渲染层不能传入或修改默认保存路径。
- 文件名继续通过 `path.basename` 收敛，下载 URL 继续经过同源校验。
- 不新增网络请求，不记录用户文件内容。
- 已发布版本没有偏好数据，首次升级按无记忆状态运行。
