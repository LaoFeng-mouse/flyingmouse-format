# 飞鼠格式鼠鼠风格 UI 重设计规格

日期：2026-07-03

## 目标

把 `飞鼠格式` 改成和 `鼠鼠打印` 同系的鼠鼠工作台风格。方向采用“B + 少量 C”：主界面仍然是清晰的文件转换工作台，同时加入少量随任务变化的鼠鼠动作。

这次改版不是普通卡通化，也不是把仓鼠头像贴到任意身体上。鼠鼠必须保持 `鼠鼠打印` 里已经形成的角色语法：低清照片质感头部、完整耳朵和脸部剪影、白色团子身体、粗黑手绘外轮廓、粉色重点色。

## 角色识别规则

### 必须保留

- 完整鼠鼠头部轮廓：不能裁圆，不能做头像徽章，不能加规则圆形边框。
- 低清照片质感：头部要保留原始梗图的颗粒感、牙齿、暗眼窝和怪笑表情。
- 白色团子身体：身体是软圆、手绘、不精细的白色块面。
- 粗黑手绘外线：线条围绕整个角色，头和身体要像同一张梗图中长出来的。
- 粉色强调色：沿用 `鼠鼠打印` 的粉色重点，用于按钮、勾选、状态强调和小道具。

### 禁止方向

- 禁止“圆形仓鼠头像 + 干净矢量身体”。
- 禁止把角色改成精致 3D、商业吉祥物、萌宠插画或普通 Q 版仓鼠。
- 禁止用公开网上表情包图片直接作为软件资产。
- 禁止让角色遮挡上传区、格式选择、转换按钮、错误原因或保存按钮。

## 视觉语言

- 页面底色：接近 `#f5f4f1` 的浅灰纸面。
- 主卡片：白底、粗黑边框、轻微硬阴影。
- 强调色：粉色 `#e95f6d`，辅助浅粉 `#ffe0e4`。
- 字体：继续使用系统中文字体，标题加粗，按钮加粗。
- 形状：卡片和按钮可使用 8-14px 圆角，保持鼠鼠打印的粗线条质感。
- 装饰：不使用渐变球、复杂背景、营销式大 hero。界面第一屏就是转换工作台。

## UI 布局

保留现有核心信息架构，改视觉和状态呈现：

1. 顶部品牌区
   - 左侧放鼠鼠基础形象或小图标。
   - 标题为“飞鼠格式”。
   - 右侧显示转换引擎状态。

2. 鼠鼠工作流条
   - 四步：选择文件、识别格式、开始转换、保存结果。
   - 每步配一个小型鼠鼠动作或道具图标。
   - 当前步骤高亮，不做复杂动画。

3. 主上传区
   - 大面积虚线/粗线边框。
   - 默认动作是“接文件鼠鼠”。
   - 拖拽时切换为“接住文件”状态。

4. 右侧控制区
   - 目标格式选择。
   - 主按钮文案可改为“鼠鼠开工”，但按钮含义必须清楚。
   - 进度、状态和错误原因仍以文字为主。

5. 支持格式区
   - 继续使用矩阵卡片。
   - 每类格式可加一个小道具，不强塞大角色图。

## 鼠鼠动作系统

动作必须重新设计，不能照搬 `鼠鼠打印` 的打印动作。第一版只做必要动作，避免资产过多。

| 状态 | 动作名 | 视觉说明 | UI 使用位置 |
| --- | --- | --- | --- |
| idle | 待命鼠鼠 | 基础站姿，完整头部 + 白团子身体 | 顶部品牌、空状态 |
| upload | 接文件鼠鼠 | 双手接住文件夹或文件页，头身保持一体 | 上传区默认/拖拽 |
| analyzing | 扫格式鼠鼠 | 戴小扫描镜或拿放大镜，检查文件 | 文件选择后、目标格式分析中 |
| converting | 开工鼠鼠 | 粉色头带，拉动简化转换机器 | 转换中、进度条附近 |
| pdf_pages | 拆页鼠鼠 | 把 PDF 拆成一叠页面卡 | PDF 转 PNG/JPG |
| ocr | 读字鼠鼠 | 戴识字眼镜，从扫描页里抽出 TXT | 图片/PDF OCR 转 TXT |
| batch | 搬运鼠鼠 | 推一车文件，不改变头身比例 | 多文件批量队列 |
| success | 完成鼠鼠 | 举带粉色勾的文件，轻微得意 | 转换成功、保存按钮附近 |
| error | 提醒鼠鼠 | 举警示牌或歪头疑惑，不遮挡错误文案 | 转换失败 |

## 资产策略

第一版建议使用新生成/新绘制的 PNG 角色动作资产，放在：

```text
public/assets/mouse-format/
```

命名建议：

```text
mouse-idle.png
mouse-upload.png
mouse-analyzing.png
mouse-converting.png
mouse-pdf-pages.png
mouse-ocr.png
mouse-batch.png
mouse-success.png
mouse-error.png
```

制作要求：

- 以 `D:\鼠鼠打印\assets\mouse_avatar.png` 和 `mouse_muscle.png` 作为本机风格参考。
- 生成/绘制时必须保留完整头部剪影，不裁圆。
- 输出应是透明 PNG 或易抠图纯色背景 PNG，最终项目引用透明 PNG。
- 每张资产都要人工预览，确认不是“头像贴身体”。
- 不直接使用网上搜索到的表情包图片作为交付资产。

## 前端状态映射

`public/app.js` 可新增一个小型状态函数，根据当前流程切换角色图：

- `idle`：无文件。
- `upload`：拖拽悬停。
- `analyzing`：选择文件后请求目标格式。
- `ready`：目标格式已识别，可复用 `idle` 或 `upload`。
- `converting`：转换进行中。
- `success`：转换成功。
- `error`：转换失败。
- `batch`：多文件队列。

不要把角色状态和后端转换逻辑耦合。角色只是前端表现层，转换 API 不变。

## 文案语气

可以加入少量鼠鼠语气，但不牺牲清晰度：

- 上传区：“把文件丢给鼠鼠”
- 转换按钮：“鼠鼠开工”
- 成功：“鼠鼠处理好了，可以保存”
- 错误：“鼠鼠没转成，原因在这里”

错误信息、格式名、保存路径、测试输出必须保持工程化准确，不写成纯玩笑。

## 验证标准

实现完成前必须检查：

- 桌面宽屏首屏无重叠、无文字溢出。
- 窄屏/移动宽度布局不遮挡按钮。
- 上传、分析、转换、成功、失败、批量状态都能看到正确鼠鼠状态。
- 角色看起来是同一个鼠鼠，不是头身混搭。
- 所有现有转换功能测试继续通过。
- 视觉截图必须人工检查，不能只看测试通过。

## 不在本轮范围

- 不改转换引擎能力。
- 不增加复杂动画系统。
- 不把鼠鼠做成完整换装系统。
- 不把扫描表格 PDF 还原 XLSX 说成已支持。
